**Плагин OpenCode для сохранения целей, автоматического продолжения, сжатия контекста, бюджетов токенов и проверки завершения по доказательствам.**

Последний релиз: [**v0.7.0**](https://github.com/demyanovvvv/opencode-target/releases/tag/v0.7.0) · [Скачать архив](https://github.com/demyanovvvv/opencode-target/releases/download/v0.7.0/opencode-target-0.7.0.tgz)

Target сохраняет цель отдельно от истории диалога и запускает следующий ход модели, пока цель
активна. Плагин учитывает расход токенов и активное время, поддерживает доказательства выполнения
требований и проверочные команды по явному запросу, останавливает работу при достижении лимитов
или повторных ошибках. Анимированный TUI-индикатор показывает состояние и расход токенов.
Вдохновлён командой Codex `/goal`.

**Новое в v0.7.0:** автоматический штатный `/compact` при пороге `100k` токенов или заполнении
`70%` окна выбранной модели. Включение: `/target context 100k`.

Решение о завершении принимает модель на основе требований и доступных доказательств.
Плагин не гарантирует достижение цели и не запускает все проверки автоматически.

## Возможности

- постоянное состояние Target с отдельным lifecycle;
- автоматическое продолжение после `session.idle`;
- бюджеты токенов, лимиты ходов и времени;
- автоматическое сжатие контекста по порогу в токенах или процентах;
- проверка требований и evidence перед завершением;
- защита от устаревших асинхронных записей;
- учёт root- и descendant-сессий;
- circuit breakers для повторных ошибок и отсутствия прогресса;
- анимированный индикатор Target в TUI OpenCode;
- автоматическая установка обоих плагинов одной командой.

Основная команда:

```text
/target <цель>
```

Короткий алиас:

```text
/t <цель>
```

## Установка

Выберите удобный язык установщика:

- [English installation](README.md#installation)
- русская установка — инструкции ниже

Требуется Node.js 22 или новее и совместимая версия OpenCode; см. [таблицу совместимости](docs/compatibility.md).
Скачайте [opencode-target-0.7.0.tgz](https://github.com/demyanovvvv/opencode-target/releases/download/v0.7.0/opencode-target-0.7.0.tgz),
распакуйте архив и откройте каталог `package`. Запустите установщик из этого каталога.
В v0.7.0 включены выбор локальной/глобальной области и отдельные деинсталляторы на обоих языках.

### Linux/macOS

```sh
sh install.sh
```

Установщик выводит сообщения на английском. Для русских сообщений используйте:

```sh
sh install.ru.sh
```

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Русская версия PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ru.ps1
```

При запуске без параметров установщик и деинсталлятор предлагают **локальную** или **глобальную**
область. Локально файлы размещаются в `<проект>/.opencode`, глобально — в каталоге конфигурации
пользователя OpenCode. Для локальной установки запрашивается каталог проекта; по умолчанию
используется текущий рабочий каталог.

```sh
sh install.ru.sh --local --project-dir /path/to/project
sh install.ru.sh --global
sh uninstall.ru.sh --local --project-dir /path/to/project
sh uninstall.ru.sh --global
```

```powershell
.\install.ru.ps1 -Local -ProjectDir "C:\Projects\my-project"
.\install.ru.ps1 -Global
.\uninstall.ru.ps1 -Local -ProjectDir "C:\Projects\my-project"
.\uninstall.ru.ps1 -Global
```

Для глобальной области установщик:

1. копирует серверный плагин в `~/.config/opencode/plugins/target.js`;
2. копирует TUI-плагин в `~/.config/opencode/tui-plugins/target.js`;
3. создаёт или обновляет `tui.json`/`tui.jsonc`;
4. добавляет TUI-плагин без дубликатов;
5. сохраняет существующие настройки и комментарии JSONC;
6. повторно включает `opencode-target-tui`, если он был отключён.

Для Windows используется эквивалентный каталог `%USERPROFILE%\.config\opencode`.
После установки перезапустите OpenCode и создайте новую сессию.

Установщик не требует `npm install`: JSONC-helper входит в release archive и запускается на Node.js.

### Обновление

Закройте OpenCode, скачайте и распакуйте [архив v0.7.0](https://github.com/demyanovvvv/opencode-target/releases/download/v0.7.0/opencode-target-0.7.0.tgz),
откройте каталог `package`, затем запустите его установщик с той же
областью и каталогом проекта. Обновляются оба плагина. Настройки и сохранённые
цели сохраняются; выводится старая и новая версия, например `0.6.0 → 0.7.0`.
Устанавливается версия из запущенного архива. Затем перезапустите OpenCode.

После перехода на v0.7.0 автосжатие изначально выключено. Для текущего диалога задайте
`/target context 100k`, для будущих сессий — `/target context default 100k`.
Команда `/target context reset` копирует default в текущую сессию. Последующие обновления
сохраняют существующие цели и настройки контекста.

### Полное удаление

Закройте OpenCode, запустите деинсталлятор и выберите область установленного плагина:

```sh
sh uninstall.ru.sh
```

```powershell
powershell -ExecutionPolicy Bypass -File .\uninstall.ru.ps1
```

Также поддерживается удаление через `sh install.ru.sh --uninstall` или `install.ru.ps1 -Uninstall`.
Удаляются оба файла плагина, его регистрации в выбранных server/TUI-конфигурациях, метаданные
установки, сохранённые цели и опустевшие служебные каталоги. Созданные установщиком конфиги
удаляются, если в них не осталось пользовательских настроек или комментариев. Повторное удаление успешно.
Другие плагины и настройки сохраняются. Английские скрипты принимают те же флаги.

Локальные цели хранятся в `<проект>/.opencode/target/state`. Глобальная установка сохраняет
текущий системный каталог и старые общие цели; локальное удаление по умолчанию их не затрагивает.
Сервер и TUI используют согласованный путь из метаданных. Локальная установка имеет приоритет
над глобальной в своём проекте. Явные `state_dir` и `--state-dir` / `-StateDir` поддерживаются;
при намеренном использовании общего каталога данных его удаление затронет всех его пользователей.

### Переменные окружения

```sh
OPENCODE_CONFIG_DIR=/custom/opencode sh install.sh
OPENCODE_TUI_CONFIG=/custom/tui.jsonc sh install.sh
```

В глобальной области `OPENCODE_CONFIG_DIR` меняет каталог конфигурации. `OPENCODE_TUI_CONFIG` указывает конкретный
TUI-конфиг. Повреждённый конфиг не перезаписывается — установщик завершается с ошибкой.

### Установка из исходников вручную

Чтобы использовать новые установщики из текущих исходников, сначала соберите файлы:

```sh
npm ci
npm run build:local
```

Затем запустите установщик по инструкции выше. Ручное копирование ниже устанавливает только
серверный плагин и использует глобальное хранилище, если явно не задан `state_dir`.

Скопируйте:

```text
dist/target.js      → ~/.config/opencode/plugins/target.js
dist/target-tui.js  → ~/.config/opencode/tui-plugins/target.js
```

И добавьте в `tui.json`:

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["./tui-plugins/target.js"]
}
```

## TUI-индикатор

Индикатор использует штатный слот `session_prompt_right` справа в панели ввода:
`│ ● Target: работа · 16.6k`. Слот проверен в OpenCode 1.18.34; отдельная сборка OpenCode для Target не нужна.
Приглушённый `│` отделяет его от элементов OpenCode. Счётчик показывает расход текущего Target:
`850`, `16.6k`, `1.2M`. Подробности и бюджет доступны через `/target status`.

| Состояние | Отображение |
|---|---|
| Работа модели | `● Target: работа · 16.6k` |
| Ожидание | `⋯ Target: ждёт · 16.6k` |
| Повтор запроса | `↻ Target: повтор · 16.6k` |
| Разрешение или вопрос | `? Target: ответ · 16.6k` |
| Пауза | `Ⅱ Target: пауза · 16.6k` |
| Блокировка | `! Target: блок · 16.6k` |
| Ограничение | `! Target: лимит · 16.6k` |
| Завершение | `✓ Target: готово · 16.6k` |

Индикатор только читает state-файл. При отключённых анимациях значок статичен.
В узком терминале сначала скрывается текст состояния, затем счётчик. Переноса строки нет.

## Команды

```text
/target <цель>                         Создать новый активный Target
/target status                         Показать состояние
/target doctor                         Проверить state и API OpenCode
/target edit <новая цель>              Изменить цель без смены lifecycle
/target pause [причина]                Приостановить Target
/target resume                         Возобновить Target
/target budget                         Показать бюджет
/target budget 250000                  Установить бюджет
/target budget off                     Убрать бюджет
/target context 100k                   Автоматический /compact при 100 000 токенов контекста
/target context 70%                    Автоматический /compact при заполнении 70% окна модели
/target context [on|off|status|reset]   Управление и диагностика автосжатия
/target context default 100k           Порог по умолчанию для новых сессий
/target clear                         Очистить сохранённое состояние
/target help                          Показать справку
```

Завершённый Target терминален. Незавершённую цель нельзя заменять новой без предварительного
завершения или очистки. Новая цель получает собственный `target_id`.

### Автоматический /compact

```text
/target context default 100k
/target Реализовать функцию и проверить результат
```

Во время активного Target плагин проверяет статистику последнего завершённого шага модели.
При достижении порога он запрашивает штатный механизм `/compact` через API `session.summarize`.
OpenCode формирует стандартное резюме, а Target сохраняет цель и продолжает работу своим scheduler.
Поддерживаются `100000`, `100_000`, `100k`, `1.5m` и целые проценты от `1%` до `99%`.
Процентный порог пересчитывается для выбранной модели. Занятая сессия может немного превысить
порог до обработки запроса сжатия.

`/target context` или `status` показывает настройки, источник, порог, последнее измерение,
окно модели, состояние запроса, ошибки и последние диагностические события. Размер контекста
включает кешированные токены и учитывается отдельно от накопленного бюджета Target.
Входные токены самого резюме не считаются размером контекста после сжатия; контексты дочерних
сессий не прибавляются к корневой.

- `context 100k` / `context 70%` — включить порог в текущем диалоге;
- `context off` — отключить, сохранив порог; `context on` — включить его обратно;
- `context default` — показать default; `default 100k`, `default 70%`, `default on/off` — изменить его;
- `context reset` — скопировать текущие настройки по умолчанию в этот диалог.

Default действует в области `state_dir` установки. Сессия получает его копию при первом
использовании; изменения default применяются к новым сессиям. Настройки переживают перезапуск
и `/target clear`; существующий диалог принимает новый default через `reset`.
Изначально функция выключена. Настройка доступна и до создания цели.

Автосжатие запускается только при активном корневом Target. При `auto_continue: false` сжатие
работает, но новый рабочий ход автоматически не начинается. Ручное сжатие также учитывается;
повторные запросы защищены блокировкой. Если первое свежее измерение после сжатия уже выше
порога, повторный запуск блокируется до снижения контекста или изменения настройки.
Три явных отказа API приостанавливают соответствующий Target: проверьте `context status`
и `/target doctor` перед возобновлением. Таймаут запроса в две минуты означает неизвестный
результат: Target остаётся активным и ждёт завершения, блокируя повторный компакт и рабочие ходы.
Позднее готовое резюме снимает блокировку и запускает планировщик, в том числе после перезапуска.
Ручная пауза и другие остановленные состояния сохраняются. Если старая установка уже поставила
Target на паузу из-за таймаута, после обновления выполните `/target resume`.
`off` отключает дополнительный автозапуск Target; штатное сжатие OpenCode может сработать раньше.

## Lifecycle

```text
active → paused → active
active → blocked
active → usage_limited
active → budget_limited
active → complete
```

Модель может завершить физический ход, но не может молча завершить активный Target. Переходы
`pause`, `resume`, `clear` и изменение бюджета принадлежат пользовательским командам. Завершение,
semantic blocked и evidence-аудит выполняются моделью через Target tools. Runtime сам применяет
лимиты использования и бюджета.

## Хранилище

Локальная автоматическая установка: `<проект>/.opencode/target/state/`.

Глобальная установка и ручное копирование без метаданных:

- Linux/macOS: `~/.local/state/opencode-target/`;
- Windows: `%LOCALAPPDATA%\opencode-target\`.

Глобальный путь можно изменить через `OPENCODE_TARGET_STATE_DIR`; установщик запоминает выбранный
путь в `target/package.json`, и оба плагина используют его после перезапуска. Явная опция `state_dir`
имеет приоритет; при её ручном изменении задайте тот же абсолютный путь для TUI.

Если OpenCode зависает, статус Orca сам по себе не подтверждает прогресс. Тайм-аут автоматического
`prompt` отправляет сигнал отмены запроса; пока исходный запрос не завершился, Target запрещает
повторный запрос и переходит в `paused`. Это не гарантирует остановку работы на стороне сервера.
В логах OpenCode ищите сервис `opencode-target`: `Target continuation prompt started`, `finished`,
`failed`, поля `sessionID`, `phase` и код ошибки. При неработающем вводе перезапустите OpenCode и
проверьте логи перед `/target resume`. Конфликт с конкретным сторонним плагином пока не подтверждён.

## Конфигурация сервера

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    [
      "opencode-target",
      {
        "max_target_token_budget": 200000,
        "auto_continue": true,
        "continuation_watchdog_ms": 60000,
        "min_continue_interval_ms": 250,
        "verification": [
          { "id": "tests", "command": "npm test", "requirementID": "tests" }
        ]
      }
    ]
  ]
}
```

`continuation_watchdog_ms` проверяет отсутствие `session.idle` после автоматического запроса.
Ожидание разрешения, ответа, а также статусы `busy`/`retry` откладывают проверку.
Недоступность API статуса сама по себе не доказывает зависание; таймер не отменяет операции хоста.
