# Contributing

## Before changing code

Read:

- `README.md` for public behavior;
- `docs/architecture.md` for lifecycle and scheduler invariants;
- `docs/state-format.md` for persistence and accounting;
- `docs/compatibility.md` for OpenCode API boundaries.

## Development setup

Use Node.js 22 LTS or newer and install the repository dependency:

```text
npm install
```

The project uses native ESM, standard Node.js modules, and `node:test`. No formatter, linter, or
bundler is required for the source build.

## Change workflow

1. Define the behavior and its authority: user command, model tool, or runtime.
2. Add a focused failing test when changing behavior.
3. Implement the smallest change that preserves stale-write and persistence invariants.
4. Update public and operational documentation if behavior, options, paths, or recovery changes.
5. Run `npm run check`.
6. Inspect the generated `dist/target.js` diff when source changes are intentional.

## Test layout

- `test/core.test.js`: state machine, persistence, accounting, parsing, and circuit breakers.
- `test/server-smoke.mjs`: plugin registration and slash command integration.
- `test/continuation-smoke.mjs`: idle scheduling and physical-turn continuation behavior.
- `test/repository.test.js`: persistence repository mutation seam.
- `test/verification.test.js`: normalized verification result contract.
- `test/continuation.test.js`: continuation phase decisions and recheck behavior.

Smoke suites wait on `hooks.whenIdle(sessionID)` after firing `session.idle` instead of polling
fixed deadlines. `SchedulerState.whenIdle` resolves once the session has no in-flight run and no
scheduled recheck, so tests observe the real completion signal. Keep it that way: a test that
loops on `Date.now()` reintroduces load-dependent flakiness.

## Generated artifact

`dist/target.js` is generated by `npm run build:local` from all modules under `src/` that make up
the local plugin, including `repository.js` and `verification.js`. Edit source files, then rebuild.
Never use the generated file as the source of truth. `npm run check` also executes
`scripts/check-dist.mjs`, which imports the generated plugin and performs a real create/verify flow.

## Pull request checklist

- Tests cover the changed behavior and relevant race/status boundaries.
- `npm run check` passes locally.
- README and docs are synchronized.
- Compatibility impact is documented.
- No secrets, local state, or generated temporary files are included.
